# 前后台捕获与输入尝试全景复盘

在《星布谷地》（基于虚幻引擎 5 开发）的自动化与辅助功能研发过程中，团队针对**画面捕获**与**按键输入模拟**两大核心底层，系统性地尝试了前台与后台运行的多种技术路线。

为了为后续开发提供参考，本文档对所有技术方案的验证过程、失效机理及最终结论进行客观复盘。

---

## 1. 图像捕获方案技术探索与评估

游戏图像捕获是自动化识别的基石。在探索过程中，我们分别对 GDI、未公开 DWM 接口、Win32 重绘以及现代 WinRT 管道进行了全面验证。

### 1.1 GDI BitBlt 方案
- **尝试目标**：利用 Win32 GDI 接口（`CreateCompatibleDC`、`BitBlt`）快速抓取前台或后台桌面及目标窗口的设备上下文。
- **运行模式**：前台与后台捕获。
- **验证结果**：**失败**。
- **失效机理剖析**：
  - 传统 GDI 能够截取基于 GDI/DirectX 9 的旧款游戏。然而《星布谷地》基于虚幻引擎 5 构建，默认使用 DirectX 12 现代翻转呈现模型（Flip Model Presentation）。
  - 在该模式下，游戏画面的后备缓冲区（Back Buffer）由 GPU 与 DWM 硬件合成器直接管理，根本不经过 GDI 兼容层。
  - 调用 `BitBlt` 抓取窗口 DC 时，返回的位图数据在绝大多数情况下为**纯黑色图像（RGB 均为 0）**；若尝试抓取全屏幕，则在游戏窗口发生遮挡时会产生严重的残影与黑块。

### 1.2 DwmSharedSurface 私有句柄方案
- **尝试目标**：通过 DWM 未公开内部接口（`dwmapi.dll` 内部导出函数）尝试获取窗口的共享 DirectX 纹理句柄（Shared Handle）。
- **运行模式**：后台高速显存直读。
- **验证结果**：**失败并彻底废弃**。
- **失效机理剖析**：
  - 该方案属于早期 Windows 系统（如 Windows 7 / 早期 Windows 10）中的逆向方案，极度依赖微软私有的未公开内部结构。
  - 在 Windows 11（特别是 22H2 / 23H2 / 24H2）以及更新的 WDDM 3.0+ 显卡驱动架构中，DWM 内部对象生命周期管理机制发生了根本性重构。
  - 强行调用私有导出函数会导致不可控的**内存访问冲突（Access Violation Exception 0xC0000005）**，极易造成宿主进程甚至 DWM 崩溃，完全丧失了工程可用性。

### 1.3 PrintWindow (PW_RENDERFULLCONTENT) 方案
- **尝试目标**：调用 `user32.dll` 的 `PrintWindow` 并传入 `PW_RENDERFULLCONTENT = 0x02` 标志。
- **运行模式**：后台窗口捕获（理论上支持被遮挡窗口）。
- **验证结果**：**局限可用（保留为备用回退引擎）**。
- **表现与局限**：
  - 在普通无边框或窗口化状态下，DWM 能够协调渲染器将游戏内容重绘至指定 HDC。
  - 但是，由于每次重绘都需要将 GPU 显存数据回读（Read-back）至系统内存，CPU 开销极大，2K 分辨率下单帧捕获延迟达 20ms - 40ms，高频调用会导致 DWM 进程高负载。
  - 此外，在部分显卡驱动配置下，该接口仍会出现黑屏；在游戏最小化时完全失效。

### 1.4 WindowsGraphicsCapture (WGC) 方案
- **尝试目标**：基于 WinRT `Windows.Graphics.Capture` 现代接口，构建 Direct3D 11 显存帧缓冲池。
- **运行模式**：前台与后台非最小化窗口捕获。
- **验证结果**：**全面成功（当前首选主力引擎）**。
- **成功原因**：
  - 官方支持的标准 API，与 DirectX 12 翻转模型完美兼容。
  - GPU 内部完成显存直接复制，延迟低至 1ms - 3ms，帧率可达 60fps+。
  - 窗口被其他应用程序任意遮挡时，均能稳定捕获到无损的游戏画面。

## 2. 输入模拟方案技术探索与评估

游戏按键触发直接决定了曲谱演奏与自动拾取的精准度与稳定性。

### 2.1 Win32 SendInput 方案
- **尝试目标**：通过 `SendInput` 构造底层 `INPUT` 结构，注入物理键盘与鼠标事件。
- **运行模式**：前台物理级模拟。
- **验证结果**：**全面成功（当前前台模式基石）**。
- **成功原因**：
  - `SendInput` 将事件直接打入操作系统输入子系统硬件队列，能被虚幻引擎 5 的 Raw Input / 物理输入监听器完美识别。
  - 响应延迟小于 0.1ms，支持高频极速连击与多键并发和弦。
  - 唯一物理限制：必须保证游戏窗口在前台且持有输入焦点。

### 2.2 Win32 传统事件（mouse_event / keybd_event）
- **尝试目标**：调用旧版 Win32 按键/鼠标 API。
- **运行模式**：前台模拟。
- **验证结果**：**淘汰**。
- **淘汰原因**：
  - 微软官方已明确将两者标记为废弃（Deprecated）。在多显示器高 DPI 环境下，`mouse_event` 的绝对坐标映射存在累积误差，统一由 `SendInput` 替代。

### 2.3 Windows 窗口消息队列方案（SendMessage / PostMessage）
- **尝试目标**：向游戏顶级或渲染子窗口句柄投递 `WM_KEYDOWN`、`WM_KEYUP` 与 `WM_CHAR`。
- **运行模式**：后台无焦点模拟（不占用用户当前的鼠标与物理键盘）。
- **验证结果**：**部分失效（受游戏引擎管线限制）**。
- **失效机理剖析**：
  - 现代大型 3D 游戏（UE5）内部普遍采用 DirectInput 或 Windows Raw Input API 进行按键状态轮询（`GetKeyboardState` / `GetDeviceState`），而不是单纯监听 Win32 消息循环。
  - 当游戏窗口失去前台输入焦点时，游戏引擎内部的按键状态轮询会直接判定所有按键为释放状态。因此向窗口投递的 `WM_KEYDOWN` 消息会被游戏内核直接忽略，导致无法触发动作。

### 2.4 桌面分身 / 独立子会话模式（Child Session）
- **尝试目标**：利用独立桌面对象（Virtual Desktop / CreateDesktop）或注入环境挂载游戏进程，使游戏在独立虚拟桌面内始终认为自己处于前台激活状态。
- **运行模式**：完全后台隔离运行。
- **验证结果**：**可行并已产品化实现**。
- **成功原因**：
  - 游戏在独立分身环境中独占虚拟输入流，前台 `SendInput` 不会与用户宿主桌面的实际键盘鼠标发生物理冲突，彻底兼顾了极高的输入可靠性与用户的多任务自由。

## 3. 技术尝试与可行性对比总览表

下表汇总了所有经过实际验证的方案、运行模式、效果表现以及最终架构裁决：

| 探索领域 | 方案名称 | 运行模式 | 实际效果与表现 | 结论状态 | 核心机理与分析 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **图像捕获** | **GDI BitBlt** | 前台/后台 | 绝大部分时间为纯黑画面；全屏遮挡时画面重影严重 | **失败 (已移除)** | UE5 采用 DX12 Flip 翻转呈现模型，绕过 GDI 重绘管线，无兼容位图句柄可供读取。 |
| **图像捕获** | **DwmSharedSurface** | 后台 (显存) | Win11 系统下直接抛出内存访问越界异常 (0xC0000005) | **失败 (已移除)** | 依赖未公开内部私有 DWM 句柄，随 Windows 系统版本与 WDDM 驱动升级而破坏性失效。 |
| **图像捕获** | **PrintWindow (0x02)** | 后台 | 窗口化下部分硬件可抓取；全屏独占下黑屏；CPU 占用高、延迟大 | **局限可用 (备用)** | 强制 DWM 重绘并回读至 CPU 内存，开销极大，且对部分显卡驱动翻转交换链不兼容。 |
| **图像捕获** | **WinRT WGC** | 前台/后台非最小化 | 稳定 60fps+，延迟小于 3ms，无视其他窗口遮挡 | **成功 (首选主力)** | 现代标准捕获管道，直接在 Direct3D 11 显存内操作表面，无损高效。 |
| **输入模拟** | **Win32 SendInput** | 前台 | 响应灵敏无漏键，毫秒级连发稳定，与物理键盘无异 | **成功 (前台基石)** | 注入系统物理级输入队列，UE5 Raw Input 能够 100% 捕获识别。 |
| **输入模拟** | **keybd_event** | 前台 | 基本可用，但在高 DPI 坐标映射下存在偏差 | **淘汰 (废弃接口)** | 属于已废弃 API，内部机制均被 `SendInput` 完全覆盖。 |
| **输入模拟** | **PostMessage 消息** | 后台 | 游戏无输入焦点时按键事件被引擎完全忽略 | **失败 (常规不可用)** | UE5 采用底层输入设备轮询状态机制，窗口失焦时直接抑制按键输入。 |
| **输入模拟** | **桌面分身 (Child Session)** | 后台隔离 | 在独立虚拟会话中运行，前台模拟与后台隔离兼顾 | **成功 (高级模式)** | 为游戏构建独立的虚拟前台上下文，既保留物理输入可靠性，又释放物理鼠标。 |
