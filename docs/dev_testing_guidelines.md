# 开发者与 AI 协同测试规范 (Testing Guidelines)

BetterPetitPlanet 属于强人类交互型 Windows 游戏辅助程序，包含 DirectComposition / Direct2D / Direct3D GPU 硬件渲染特效、WPF 桌面窗口、WinRT 屏幕帧捕获、DirectML 硬件加速 OCR 以及 Win32 硬件键盘模拟。

为了杜绝自动化测试意外弹出系统窗口、抢占焦点或发送键盘事件干扰用户环境，同时避免编写和维护大量脆弱、虚假的 UI / GPU 视觉模拟测试，特制定本规范。所有人类开发者与 AI Agent 均须严格遵守。

---

## 核心原则

### 1. 默认优先编译验证
- 日常功能开发、常规重构与小修补，默认优先通过 `dotnet build` 验证语法正确性、类型契约、依赖关系与工程完整性。
- 确保构建过程零警告、零错误即可进入后续审查，不以新增测试用例数量作为衡量代码提交的标准。

### 2. 纯逻辑核心测试极简保留
- 仅对以下底层无副作用的关键纯逻辑模块保留并针对性运行单元测试（约 25 个核心测试）：
  - **核心算法与数学计算**：时钟计算、GPU 几何变换与命中判定逻辑（纯数学模型）；
  - **数据解析与转换**：简谱解析（PetitScoreParser）、外部谱面适配器（SourceChartAdapter）；
  - **配置与输入安全防护**：配置死锁防护、按键冷却与释放重试、皮肤包导入安全沙箱（Zip Slip / 路径穿越防护）。
- 仅在对上述核心模块进行实质性修改时，才按需单独执行对应的纯逻辑测试。

### 3. 拒绝教条化 TDD 与虚假覆盖率
- 本项目不强制采用测试驱动开发（TDD）。
- 不片面追求单元测试代码覆盖率指标。
- 严禁在日常修改、小修复或 UI 调整过程中盲目新建脆弱或低价值的测试文件。

### 4. 真实端到端用户验收
- 以下复杂交互与图形渲染能力，由真实用户在实际 Windows 桌面环境下端到端体验与验收：
  - DirectComposition GPU 悬浮窗特效与 24 款参考皮肤视觉表现；
  - WPF 窗口与设置面板渲染；
  - DirectML OCR 物品文字识别准确度；
  - 真实游戏前后台状态与音画同步体感。

### 5. 绝对安全红线（严禁侵入式测试）
- **严禁编写或执行** 任何会创建真实桌面窗口、调用 Win32 API 抢占前台游戏焦点或通过 SendInput / PostMessage 发送系统按键的自动化测试。
- 严禁在未经受限的环境中执行全量 `dotnet test`，杜绝任何对宿主操作系统或正在运行的游戏产生副作用的操作。
